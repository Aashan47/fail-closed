## Port 18080 during the run, checked rather than assumed

During teardown I found a process listening on 18080 and stopped to establish whether
anything other than the container under test could have answered the Check's curl,
because a PASS sourced from a stray listener would be worthless:

    $ lsof -nP -iTCP:18080 -sTCP:LISTEN
    ssh  55038  ...  TCP *:18080 (LISTEN)
    $ ps -o pid,lstart,command -p 55038
    55038  Sat Sep 26 18:49:42 2026  ssh: /Users/aashanjaved/.colima/_lima/colima/ssh.sock [mux]

It is Colima's SSH multiplexer — the mechanism by which a container's published port
reaches the host on this Docker backend. It is not a service and it is not a
confounder; it is how `-p 18080:8080` works here. Confirmed by removing the container
and re-probing:

    $ docker ps -a                       (no containers)
    $ curl -fsS -m 5 http://127.0.0.1:18080/health
    curl: (7) Failed to connect to 127.0.0.1 port 18080 after 0 ms
    curl exit=7

With the container gone, nothing answers on 18080. The listener existed because of the
container and disappeared with it, so the `{"status": "ok"}` in the Check's output came
from the image built at this revision and from nothing else.
