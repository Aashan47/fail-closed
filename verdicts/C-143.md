## A defect in my own recording harness, and the re-run that settles it

This verdict was first generated as a FAIL. That was wrong and the fault was mine, not
the Check's. My batch driver recorded each exit status to a file; for this one claim I
wrote `echo "C-143 EXIT=$?" | tee C-143.exit`, so the file received the literal string
`C-143 EXIT=0` instead of `0`. The generator compared that against `"0"`, did not match,
and produced a FAIL on the single claim that settles the §2 no-egress rule.

    $ od -c C-143.exit        (first run)
    0000000  C - 1 4 3   E X I T = 0 \n        <- a label, not a status
    $ od -c C-144.exit        (normal)

The output had said `{"status": "ok"} NO EGRESS` throughout, which is printed only on the
success path — every failure path in this Check exits 1, 2, 3 or 4 before reaching that
echo. I could have corrected the file by hand on that reasoning. I re-ran the Check
instead, under the §8 lock, so the recorded status is a status that was actually
recorded rather than one I reconstructed from the output:
